# TazaBatch

Оригинальный ограниченный процесс по направлению reference11 n8n: опубликованная упорядоченная цепочка очистки синтетической таблицы → полный отчёт каждого шага → один явный локальный импорт всего успешного пакета. Это собственный рабочий кабинет, а не n8n, облачная автоматизация или коннектор.

Admin задаёт цепочку и оба авторских описания RU/KK, затем5–7 разных шагов с уникальной позицией1–20. Обязательны проверки code/label/city, разбор qty и последний unique_code; дополнительно trim_all и upper_code. Порядок имеет значение: integer_qty до trim_all отказывает числу с пробелами. Публикация фиксирует точную версию/снимок; повтор версии запрещён даже после архива. Полных промежуточных версий черновика нет.

JSON-массив1–50 объектов: ровно code,label,city,qty, все значения строки до200 знаков(qty до24). Повтор decodedключа, неизвестный/пропущенный ключ, вложения/массивы/нестроковые значения отклоняются. Синтаксический/предметный отказ сохраняется как rejected отчёт без импорта. JSON не CSV, не произвольная схема. Raw поле до50000 знаков, внешние пробелы обрезает общий парсер.

trim_all обрезает края всех строк; upper_code использует стандартный Unicode toUpperCase без NFKC/перевода/транслитерации; require_* проверяет непустой trimтекст; integer_qty принимает только канонические десятичные цифры1–10000 без нуля/знака/ведущихнулей/дроби/экспоненты; unique_code сравнивает точные итоговые строки с учётом регистра и пробелов. Первая ошибочная стадия фиксирует before/after и все свои ошибки и останавливает цепочку; более поздние шаги не выполняются. Частично преобразованные строки остаются только в отчёте. Импортируется весь output успешного отчёта, без частичной записи.

Все сотрудники читают общую область. Admin редактирует/публикует/архивирует/копирует; staff запускает синтетические пакеты и только автор явно импортирует успешный отчёт один раз с основанием. Admin не обходит авторство. Импорт создаёт неизменный отдельный локальный набор, а не заказ/склад/CRM/услугу; одинаковые code между разными импортами разрешены, уникальность только внутри пакета. Архив цепочки/публикации закрывает новые прогоны, прежний ready можно импортировать по снимку. Rejected и уже imported отчёт можно скрыть архивом; ready до импорта нельзя. Архив импорта не отменяет набор и не разрешает повтор. Нет отмены/повтора шага/отката импорта/редактирования истории.

Общая revision в BEGIN IMMEDIATE защищает все команды, включая несвязанные изменения. UUID requestKey глобально расходуется при сохранении отчёта/импорта; повтор отказывает, не молчаливый успех. Preview/hash не обязателен HTTP и не доказывает чтение человеком. Клиент не назначает output/trace/owner/time/digest. Clockrollback до отчёта запрещает импорт. JSON/hash не подписаны: согласованность не подлинность; accounts/auth/audit исключены, restore только пустая область; HTTP JSON2МБ, полную SQLite резервировать согласованно отдельно.

Нет внешних вызовов/коннекторов/n8ncode/секретов/AI/LLM/cron/webhook/импорта настоящих данных/сообщений/платежей. Никакого спроса, клиента, экономии или результата услуги не подтверждено. Нужен автор процесса для реального применения.

Operate расширение собственного Shared Work Cabinet: наследовать QuralGate DESIGN и navy/paleblue/green, native labelled forms, видимый фокус. Узкая задача/пределы/наследуемый мир определены поручением автономно продолжать100; отдельная дизайн-пауза не нужна. Первым экраном результат пакета: исход, версия, автор, число строк и причина остановки; затем упорядоченный trace и явный owner-import. От QuralGate отличается несколькими преобразованиями и настоящим локальным набором, от SynaRoute — преобразованием строк, не классификацией/actual-vs-expected.
